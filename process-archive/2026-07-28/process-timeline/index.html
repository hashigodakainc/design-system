2026.07.25–29 / Corporate site

装飾から、
理解の順序へ。

Our ConceptからNews、Follow Us、Contact完了状態まで、01C-Cを置くことよりも、顧客が何をどの順序で理解するかを優先した。比較HTMLに残る探索と、実サイト上で確定した情報設計・レスポンシブ・操作・検証環境の判断を、重複を避けて一つの時系列へまとめる。

01 / Our Concept考え方の提示

07.25 / Visual

HeroのG案を転用せず、Concept専用の01C-Cへ

BEFOREHero候補Gの拡散境界を背景として再利用
→
AFTER「作れる」を「届けられる」へつなぐ01C-Cを、本文と対になる大判背景へ

理由: Heroと同じ視覚効果を反復するより、会社の役割をセクション固有の構図へ翻訳した方が、コピーと図像の意味が一致するため。

07.25 / Scroll

固定演出をやめ、通常フローで行をリヴィール

BEFOREセクションを固定し、長いスクロール距離で本文を進行
→
AFTER通常スクロールの中で、開始を遅らせた行単位リヴィール

理由: Serviceへの遷移でカクつきを生まず、アニメーションへ気づける開始点と余韻だけを残すため。

07.25 / Background

画像の地色を透明にする

BEFORE画像側の白に近い背景色とHero背景がわずかに不一致
→
AFTER透過画像をHeroと同じCSS背景色へ重ねる

理由: レスポンシブ時も境界を出さず、背景色の正本をデザイントークンへ一本化するため。

BEFORE共通ガター内の薄いグレーカードに低濃度01C-C
→

理由: 淡いPrimaryのセクション背景と白い情報面を明確に分け、見出しと記事一覧だけへ視線を絞るため。見出しの読み始めは他セクションと同じ共通ガターへ維持する。

07.28 / Contents

BEFORE1件でも固定最小高を持ち、遷移操作がない
→
AFTER最大3件まで内容量で可変。「もっと見る」はPC右上、モバイルは一覧後の右下

理由: 件数が少ない時の空白をなくし、一覧を邪魔しない位置へ次の閲覧段階を示すため。ボタンはPrimaryのホバー・フォーカス仕様へ揃える。

07.28 / Mobile rhythm

BEFOREモバイルのカード上余白190pxで、Newsだけ見出しと内容が離れる
→
AFTER上余白を152pxへ縮め、記事行と下部ボタンの余白は維持

理由: 可読性や操作領域を削らず、News内の情報同士の距離だけを他セクションの密度へ揃えるため。

07.28 / Destination

「もっと見る」は詳細ではなく一覧へ

BEFORE遷移直後に最初の記事詳細を表示
→
AFTERトップと同形式のニュース一覧を表示し、記事行から個別詳細へ進む

理由: 情報を探す段階と本文を読む段階を分け、件数が増えても同じ導線を維持するため。

08 / UI foundation部品とCSSの一本化

07.28 / Radius

ボタンとカードの角丸を役割で分ける

BEFOREボタンは2pxまたは直角、カードは0〜20pxが混在
→
AFTERPrimary／Secondaryは4px、白いコンテンツカードは8px、Tertiaryは0

理由: 矩形の明快さを残しながら、操作部品と情報面の階層を最小限の丸みの差で識別するため。

07.28 / Legacy CSS

新旧CSSの併用を終える

BEFORE現行CSSと旧responsive.cssが同時に読み込まれ、旧DOM用指定が干渉
→
AFTER必要なモバイル挙動だけ移植し、responsive.cssの参照と本体を削除

理由: 見た目の問題を上書きで抑えず、旧セレクタが現行UIへ届く競合経路そのものをなくすため。

07.28 / Naming

世代表記を外し、現在の正本を一意にする

BEFORE完全移行後もhomepage-v2.css／contact-v2.cssという名称
→
AFTERhomepage.css／contact.cssへ改名し、参照と文書も統一

理由: 並行する旧版がない状態で世代表記を残さず、どのファイルが現行の正本かを名称から判断できるようにするため。

BEFORENews見出し領域の下端に横罫線
→

07.28 / Content cards

BEFORE見出し後のCanvasへ記事一覧・本文を直接配置
→

11 / Responsive compositionデスクトップの意図をモバイルへ

07.28 / Hero motif

粒子を縮めるだけでなく、同じ構図として再投影する

BEFORE実viewport比へ同じ倍率で投影し、縦長画面では左右が切れ、粒子密度も高い
→
AFTER16:9構図を横幅へ合わせ、390pxでは粒子を37.5%へ均等に減らして画面高14%分上へ

理由: 01C-Cの輪郭、遠近感、粒子のリズムをデスクトップと同じものとして認識でき、コピー周辺の余白も確保できるため。ランダム間引きは局所的な疎密を生むため、4×4区画ごとに同数を残す。

07.28 / Hero-Concept type

文字を小さくせず、利用幅と字間で孤立行を防ぐ

BEFOREHeroが3行になり、Conceptでは「へ。」「す。」だけが次行へ孤立
→
AFTERHeroを指定2行へ固定し、Concept見出しと対象本文行だけ字間・利用幅を補正

理由: 見出しの力と本文の読書余白を保ったまま、数pxの不足が生む不自然な折り返しだけを解消するため。本文全体を余白外へ広げない。

07.28 / Service cards

モバイルのAS IS / TO BEを、枠ではなく状態ラベルで読む

BEFORE枠線付きカードと小さな矩形ラベル。途中で64pxの円形も比較
→
AFTER枠線なしの面へ、72×40px・4px角丸の長方形ラベルを左上に重ねる

理由: 円形バッジとして強く独立させず、カードへ接続した状態タブとして読ませるため。ラベル左端はService見出しの16pxへ揃え、カード本体を12px内側へ置く。

07.28 / Service hierarchy

概要見出しの強さを保ち、補助情報を一段退ける

BEFOREAS IS見出しを縮小して折り返しを避け、本文と支援ピルも近い文字強度
→
AFTER見出しは19pxのまま利用幅を12px広げ、本文13〜14px、支援ピル11px・枠線なし

理由: 見た目に残る余白を見出しへ使い、課題→説明→支援内容の順序を文字サイズと面の軽さで明確にするため。

07.28 / Service spacing

サービス内は近づけ、概要から詳細への切り替えは離す

BEFORE図と文章は32px離れ、全体像とService 01は48pxだけで連続
→
AFTER図と文章は16px、AS IS / TO BEの全体像からService 01までは112px

理由: 同じサービスの要素は一まとまりにし、概要から個別詳細へ移る大きな階層だけをサービス間より明確に離すため。

07.28 / Team mobile

4名を2列で一覧し、全文はモーダルへ分ける

BEFOREモバイル1列、または2列化後も長い経歴本文をすべて表示
→
AFTER2×2配置、本文7行フェード、タップで経歴全文のプロフィールモーダル

理由: チーム全体の一覧性と、個別プロフィールの読みやすさを両立するため。閉じるボタン、背景タップ、Esc、キーボード操作へ対応する。

07.28 / Mobile gutter

ページ種別ごとの外周差を16pxへ統一

BEFOREトップ24px、下層・Header・メニュー40pxなど、同じ画面幅で基準が分散
→
AFTER760px以下のトップ・下層・共通シェル・メニューを左右16pxへ

理由: ページ遷移やメニュー開閉で読み始めと操作位置を動かさないため。カード固有の内側余白とデスクトップの流動ガターは維持する。

Mobile gutter 16px
07.28 / News mobile

カード幅と記事の読み順をモバイルへ合わせる

BEFOREトップカード内の余白が混在し、メタ情報とタイトルが左右に分かれる。詳細カードは左右40px
→
AFTERトップは外周・内側とも16px。日付／カテゴリの次に15pxタイトル。詳細カードも左右16pxへ

理由: 限られた横幅をタイトルへ渡し、トップ・一覧・詳細の開始位置をページ見出しと一貫させるため。デスクトップタイトルも17pxへ一段下げた。

12 / Motion and navigation再訪しても破綻しない操作

07.28 / Shared mobile header

詳細ページも「ロゴ＋メニュー」へ統一する

BEFOREページ固有CSSが残り、トップと詳細でCTAやハンバーガー位置が異なる
→
AFTER共通シェルを表示規則の正本にし、ロゴ左端とハンバーガー／閉じる右端を16pxへ

理由: ページ固有の再描画後も同じ見た目と操作を保つため。開閉はdocumentへのイベント委譲とし、DOM差し替え後も動作させる。

07.28 / Mobile menu

線と独立CTAを外し、5つの通常メニューへ

BEFORE罫線、右矢印、下部の問い合わせCTA、メールアドレスが役割を重複
→
AFTER20px・太字の5項目と下部Copyrightだけを、外周16pxの同じ左端へ

理由: 「お問い合わせ」を他の遷移先と同じナビゲーションとして扱い、線や矢印がなくても文字の強さと整列で選択肢を読めるため。

07.28 / Menu motion-focus

開閉を対にし、初期フォーカスの一瞬のずれをなくす

BEFORE全画面と項目を同時表示し、閉じる時は即時。開いた直後に「×」の標準枠がずれて見える
→
AFTER白面を上から展開して項目を順次表示し、閉じる時は逆再生。初期フォーカスはメニュー面へ

理由: 開閉の因果を保ち、意図しないフォーカス枠のフラッシュだけを防ぐため。Tab後の可視フォーカス、循環、Esc、復帰先は維持する。

07.28 / Contact mobile

写真を寄せ、情報は左から読ませる

BEFOREモバイルも中央揃えで、写真全体を広く見せる
→
AFTER見出し・説明を左揃え、背景高115%の寄った写真、ラベル「お問い合わせ」

理由: 人物は気配として残しながら、狭い画面では見出しからCTAまで一つの左軸で読ませるため。Footerの問い合わせもフォーム詳細へ直接遷移する。

07.28 / Contact CTA
