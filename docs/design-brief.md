# Hashigodakaデザインシステム 制作ブリーフ

## 目的

Hashigodakaの暗黙のデザイン感覚を、メンバーとAIエージェントが再利用できる組織資産へ変換する。
人間が方向性を判断できることに加え、各メンバーのAIが一貫した成果物を生成・検証できる状態を
完成条件とする。

## 想定する成果物

- ビジュアルの方向性とデザイン原則
- 色、書体、余白、角丸などのデザイントークン
- ロゴ、アイコン、画像などの承認済み資産
- UI、文書、スライド、図解などへの適用例
- 推奨例、避ける例、判断理由
- AIエージェントが参照できる機械可読な定義
- Codex、Claude Codeなどへ配布するための薄いアダプター
- 同じ課題を複数のAIへ渡して再現性を確認する検証方法

## 現在の進め方

1. Hashigodakaの事業、顧客、約束する価値から、比較に使う二つの視覚軸を定める。
2. 4象限のムードボードを一時領域のローカルHTMLで作り、参照例を比較する。
3. 中心となる領域、隣接領域から借りる要素、避ける領域を選ぶ。
4. 選定理由をデザイン原則へ変換し、トークンと資産へ落とす。
5. 人間向けガイドとAI向け定義を同じ正本から提供する。
6. 別のメンバーのAI環境へ配布し、同じ制作課題で再現性を検証する。

## 記事化

制作過程は、外部リポジトリ `maguroid/posts` の記事ワークフローに従って記事化する。
公開記事の中心は、ムードボード単体ではなく「Hashigodakaのデザインシステムを作成し、
メンバーのAIへ配布できるようになるまで」とする。

検証の生データ、失敗、当初仮説、判断変更は記事の編集メモへ残し、公開本文は読者が再利用できる
判断モデルとして構成する。記事用画像には自作素材または掲載権を確認した素材だけを使用する。

## 現時点の仮説

- 会社の提供価値から、技術的な精密さと静かな信頼感が中心方向になる可能性がある。
- AIが派手さを演出すること自体は価値にせず、成果と品質への責任が視覚的にも伝わる必要がある。
- 形容詞だけで方向を指定するより、複数の参照例から選び、避ける方向も示すほうがAIへ伝わりやすい。

これらは確定した原則ではなく、ムードボードと実制作を通じて検証する。
