# レイアウト

Hashigodakaのレイアウトは、大きなタイポグラフィや一つの強いビジュアルを、明確な整列と広い余白で
支える。数値は `tokens/layout.json` を正本とし、実装では `styles/tokens.css` のCSS変数を使う。

## 余白スケール

基本単位は4pxとし、次の尺度だけを使う。

| Token | Value | 主な用途 |
| --- | ---: | --- |
| `space.1` | 4px | 密接したラベル内の微調整 |
| `space.2` | 8px | アイコンと文字、見出しと補助情報 |
| `space.3` | 12px | 小さな要素群 |
| `space.4` | 16px | コンポーネント内部の標準間隔 |
| `space.5` | 24px | カード内余白、グリッドの溝 |
| `space.6` | 32px | 大きなコンポーネント内部 |
| `space.7` | 48px | 小セクション、関連ブロック間 |
| `space.8` | 64px | 標準セクション、内容のインデント |
| `space.9` | 96px | 大セクション、ページの主要な区切り |
| `space.10` | 128px | 特別に強い余白が必要な場面 |

値を選ぶときは、隣接する要素同士の関係が伝わる最小の値を使う。独自の中間値を追加する前に、
要素のグループ分けや情報階層を見直す。

## ページ余白とコンテンツ幅

| 役割 | Mobile | Tablet | Desktop |
| --- | ---: | ---: | ---: |
| Page gutter | 24px | 48px | 64px |
| Grid columns | 4 | 8 | 12 |
| Grid gutter | 16px | 24px | 24px |

コンテンツの最大幅は用途で分ける。

- `Reading / 720px`: 本文、説明、フォームなど、読みやすさを優先する領域
- `Standard / 1120px`: 一般的なページ本文、一覧、複数カラム
- `Wide / 1440px`: 写真、図解、データ表など、広さに意味がある領域

画面幅が最大幅を超えても、内容を無制限に引き伸ばさない。最大幅の外側はページ余白として扱う。

## セクション間隔

- `Small / 48px`: 同じ主題に属する小さな区切り
- `Medium / 64px`: コンパクトなセクション、Mobileの標準セクション
- `Large / 96px`: Desktopの主要セクション

セクション間隔は単なる装飾ではなく、話題の切り替わりと優先度を示す。すべてをLargeにせず、
同じ主題の内部はSmallまたはMediumでまとめる。

## ブレークポイント

- Mobile: `760px`以下
- Tablet: `1050px`以下
- Wide: `1440px`以上

ブレークポイント名は端末を保証するものではない。内容が窮屈になる地点で、列数、配置、ナビゲーションを
切り替えるための共通境界として使う。CSSカスタムプロパティはメディアクエリ条件へ使えないため、
実装時の数値は `tokens/layout.json` と一致させる。

## 実装例

```css
.page {
  padding-inline: var(--hsg-layout-page-gutter-desktop);
}

.article {
  max-width: var(--hsg-layout-content-width-reading);
}

.section {
  padding-block: var(--hsg-layout-section-space-large);
}
```

## 運用ルール

- 生の数値より、用途別のレイアウトトークンを優先する。
- コンポーネント内部だけで完結する間隔には、余白スケールを使う。
- 余白を狭める前に、情報量、見出し階層、要素の重複を見直す。
- 写真、図形、大見出しを同時に主役にせず、余白で視線の順序を作る。
- レスポンシブ対応は縮小ではなく再配置として設計する。
